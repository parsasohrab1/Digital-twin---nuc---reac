در ادامه، یک **نرم‌افزار الزامات (SRS) کامل و یکپارچه** بر اساس آخرین نسخه تخصصی‌شده محصول (متمرکز بر نیروگاه هسته‌ای با PINN، تطبیق بلادرنگ EKF، پیش‌بینی گذرا با LSTM-ARIMA، شبیه‌سازی انبوه سناریو و DSS هسته‌ای) ارائه می‌شود.

این سند مطابق با **IEEE Std 830-1998** و الزامات ثبت اختراع ایران تنظیم شده و شامل تمام بخش‌های لازم برای یک سند مهندسی الزامات نرم‌افزاری قابل تحویل است.

## 1. معرفی

### 1.1 هدف سند

این سند الزامات نرم‌افزاری (SRS) برای **سیستم دوقلوی دیجیتال هسته‌ای (Nuclear Digital Twin – NDT)** را مشخص می‌کند. هدف سیستم، ایجاد یک مدل شبیه‌سازی بلادرنگ از رفتار حرارتی-هیدرولیکی قلب راکتور و مدار اول نیروگاه هسته‌ای با قابلیت‌های زیر است:

- شبیه‌سازی بلادرنگ میدان‌های دما، فشار و سرعت خنک‌کننده با استفاده از **شبکه عصبی آگاه از فیزیک (PINN)**
- **تطبیق خودکار پارامترهای فیزیکی** قلب راکتور (ضریب زبری میله سوخت، ضریب رسوب، ضریب افت فشار) بدون توقف راکتور
- **پیش‌بینی زودهنگام گذراهای ایمنی** (LOFA، LOCA کوچک، جوش بحرانی DNB) با شبیه‌سازی انبوه سناریوهای «چه-اگر»
- **سیستم پشتیبان تصمیم‌گیری هسته‌ای (Nuclear DSS)** برای ارائه اقدامات اصلاحی رتبه‌بندی‌شده به اپراتور اتاق کنترل

### 1.2 دامنه محصول

سیستم به عنوان یک **لایه نرم‌افزاری هوشمند** بر روی سیستم I&C موجود نیروگاه هسته‌ای نصب می‌شود. دامنه شامل:

| جزء | توضیح |
|------|--------|
| دریافت داده | اتصال به حسگرهای فشار، دما، دبی و نوترونی از طریق OPC UA / Modbus |
| مدل PINN | پیش‌بینی مستقیم میدان‌های حرارتی-هیدرولیکی قلب راکتور |
| واحد تطبیق | به‌روزرسانی پارامترهای فیزیکی با EKF در کمتر از ۱۰۰ میلی‌ثانیه |
| واحد پیش‌بینی | تحلیل روند (LSTM+ARIMA) و شبیه‌سازی ≥۵۰۰ سناریو روی GPU |
| DSS | بهینه‌سازی چندهدفه (Pareto Front) و رتبه‌بندی اقدامات ایمنی |
| رابط کاربری | داشبورد اتاق کنترل تحت وب با تأخیر <۲۰۰ میلی‌ثانیه |

### 1.3 تعاریف و اختصارات

| عبارت | تعریف |
|-------|--------|
| **PINN** | Physics-Informed Neural Network – شبکه عصبی آگاه از فیزیک |
| **EKF** | Extended Kalman Filter – فیلتر کالمن توسعه‌یافته |
| **LSTM** | Long Short-Term Memory – حافظه کوتاه‌مدت طویل |
| **ARIMA** | AutoRegressive Integrated Moving Average |
| **DSS** | Decision Support System – سیستم پشتیبان تصمیم‌گیری |
| **LOFA** | Loss of Flow Accident – حادثه کاهش جریان خنک‌کننده |
| **LOCA** | Loss of Coolant Accident – حادثه خروج خنک‌کننده |
| **DNB** | Departure from Nucleate Boiling – جوش بحرانی |
| **RPV** | Reactor Pressure Vessel – مخزن تحت فشار راکتور |
| **DNBR** | Departure from Nucleate Boiling Ratio – نسبت ایمنی جوش بحرانی |
| **TTE** | Time to Event – زمان باقیمانده تا رویداد |
| **RUL** | Remaining Useful Life – عمر باقیمانده مفید |

### 1.4 ارجاعات

| مرجع | عنوان |
|-------|-------|
| IEEE 830-1998 | Recommended Practice for Software Requirements Specifications |

## 2. توضیحات کلی

### 2.1 چشم‌انداز محصول

سیستم NDT به عنوان یک **افزونه هوشمند** بر روی سیستم I&C موجود نیروگاه هسته‌ای نصب می‌شود. داده‌ها از حسگرهای موجود (و چند حسگر اضافی پیشنهادی) دریافت شده، پردازش می‌شوند و خروجی به داشبورد اتاق کنترل ارسال می‌گردد. سیستم **به صورت مستقل** عمل کرده و خروجی آن تنها پس از تأیید اپراتور قابل اعمال است (حالت نیمه‌خودکار).

### 2.2 کاربران سیستم

| نقش | توضیح |
|------|--------|
| اپراتور ارشد راکتور | استفاده از داشبورد، مشاهده هشدارها و توصیه‌های DSS |
| مهندس ایمنی هسته‌ای | تحلیل خروجی‌ها، تنظیم آستانه‌های ایمنی |
| مهندس سیستم I&C | نگهداری، کالیبراسیون اولیه، به‌روزرسانی مدل PINN |
| مدیر نیروگاه | دریافت گزارش‌های خلاصه و آمار عملکرد سیستم |

### 2.3 محدودیت‌های طراحی (ویژه هسته‌ای)

| محدودیت | مقدار |
|----------|--------|
| بیشینه تأخیر end-to-end | ≤ ۵۰۰ میلی‌ثانیه |
| بیشینه زمان شبیه‌سازی هر سناریو | ≤ ۱۰ میلی‌ثانیه |
| بیشینه زمان شبیه‌سازی ۵۰۰ سناریو | ≤ ۱ ثانیه |
| دقت پیش‌بینی دما (نسبت به حسگرها) | خطای نسبی ≤ ۲٪ |
| دقت پیش‌بینی فشار | خطای نسبی ≤ ۵٪ |
| حداکثر زمان عدم اتصال به حسگرها (قبل از هشدار) | ۳ ثانیه |
| فرکانس نمونه‌برداری از حسگرها | ≥ ۱۰ هرتز |
| بافر ذخیره پارامترهای فیزیکی | ≥ ۱۰۰۰ نمونه |
| حافظه GPU مورد نیاز | ≥ ۱۶ گیگابایت |
| دمای عملیاتی سرور (مطابق استاندارد هسته‌ای) | ۵ تا ۴۰ درجه سانتی‌گراد |

### 2.4 مفروضات و وابستگی‌ها

- حسگرهای فشار، دما و دبی در نقاط کلیدی مدار اول نصب شده‌اند.
- سرور GPU در اتاق کنترل با خنک‌کاری مستقل مستقر است.
- اپراتور دارای دسترسی به صفحه نمایش با رزولوشن حداقل ۱۹۲۰×۱۰۸۰ است.
- سیستم I&C موجود از پروتکل OPC UA پشتیبانی می‌کند.
- داده‌های طراحی راکتور (هندسه، خواص مواد، نقشه مجتمع‌های سوخت) در دسترس است.

## 3. نیازمندی‌های عملیاتی (ویژه هسته‌ای)

### 3.1 حالت‌های عملیاتی سیستم

| حالت | توضیح | زمان فعال شدن |
|------|--------|----------------|
| **آموزش اولیه (Offline Training)** | آموزش PINN بر اساس داده‌های شبیه‌سازی (مانند RELAP5) | قبل از بهره‌برداری، حدود ۲۴ ساعت |
| **کالیبراسیون (Calibration)** | تخمین اولیه پارامترهای فیزیکی با داده‌های واقعی ۷ روز اول | ۷ روز اول پس از نصب |
| **عملیات عادی (Normal Operation)** | حلقه بسته تطبیق + پیش‌بینی + نمایش | در تمام زمان‌های دیگر |
| **حالت گذرا (Transient Mode)** | شبیه‌سازی انبوه سناریوها + DSS فعال | به‌طور خودکار در صورت عبور نرخ پارامتر از آستانه |
| **حالت ایمنی (Safe Mode)** | در صورت قطع ارتباط با حسگرها، ادامه با آخرین پارامترها | پس از ۳ ثانیه قطعی |

### 3.2 الزامات启动 (Startup)

| نیاز | شرح |
|------|------|
| NDT-ST-01 | زمان راه‌اندازی سرد (از روشن شدن سرور تا آماده‌باش) ≤ ۲ دقیقه |
| NDT-ST-02 | بارگذاری آخرین نسخه مدل PINN از حافظه غیرفرار |
| NDT-ST-03 | اتصال خودکار به گیت‌وی OPC UA در کمتر از ۱۰ ثانیه |
| NDT-ST-04 | تأیید صحت سنسورها (min/max) قبل از ورود به عملیات عادی |

### 3.3 الزامات خاموشی (Shutdown)

| نیاز | شرح |
|------|------|
| NDT-SD-01 | ذخیره خودکار آخرین پارامترهای فیزیکی (ε_fuel, R_f, K_spacer) قبل از خاموشی |
| NDT-SD-02 | ذخیره آخرین ۱۰۰۰ نمونه داده حسگر در پایگاه داده |
| NDT-SD-03 | ایجاد گزارش خلاصه از آخرین ۲۴ ساعت عملیاتی |

## 4. نیازمندی‌های رابط

### 4.1 رابط کاربری (UI)

#### 4.1.1 داشبورد اصلی اتاق کنترل

| UI-RQ-01 | نمایش نقشه حرارتی (Heatmap) قلب راکتور در مختصات (r,θ,z) با بروزرسانی ≤ ۲۰۰ میلی‌ثانیه |
| UI-RQ-02 | نمایش عددی دما، فشار و دبی در نقاط کلیدی (ورودی قلب، خروجی قلب، حلقه اول) |
| UI-RQ-03 | نمایش DNBR (نسبت ایمنی جوش بحرانی) برای داغ‌ترین مجتمع سوخت |
| UI-RQ-04 | نمایش زمان تخمینی تا رویداد (TTE) برای هر هشدار فعال |
| UI-RQ-05 | نمایش سه اقدام اصلاحی پیشنهادی DSS با رتبه ایمنی (۱ تا ۵) و احتمال موفقیت |
| UI-RQ-06 | دکمه «تأیید اقدام» برای ارسال دستور به سیستم کنترل (با تأیید دو مرحله‌ای) |
| UI-RQ-07 | حالت «شب» با نور کم (Dark mode) برای اتاق کنترل |

#### 4.1.2 صفحه تنظیمات و پیکربندی

| UI-RQ-08 | تنظیم آستانه‌های ایمنی (دمای مجاز غلاف، DNBR بحرانی، نرخ مجاز تغییر زبری) |
| UI-RQ-09 | مشاهده و ویرایش پارامترهای اولیه مدل PINN |
| UI-RQ-10 | بارگذاری مجدد مدل PINN از فایل |
| UI-RQ-11 | مشاهده لاگ رویدادها و هشدارهای ۳۰ روز گذشته |

### 4.2 رابط سخت‌افزاری (I/O)

| HW-RQ-01 | پشتیبانی از پروتکل OPC UA (Client) برای دریافت داده از PLC هسته‌ای |
| HW-RQ-02 | پشتیبانی از Modbus TCP به عنوان جایگزین |
| HW-RQ-03 | ایزولاسیون گالوانیکی بین سرور و شبکه کنترل اصلی |
| HW-RQ-04 | پشتیبانی از خروجی دیجیتال (باینری) در صورت فعال‌سازی حالت خودکار (اختیاری) |
| HW-RQ-05 | نرخ نمونه‌برداری قابل تنظیم از ۱ تا ۱۰۰ هرتز |

### 4.3 رابط نرم‌افزاری (API)

| API-RQ-01 | REST API برای دریافت وضعیت سیستم به صورت JSON |
| API-RQ-02 | امکان درخواست شبیه‌سازی دستی یک سناریوی خاص (توسط مهندس ایمنی) |
| API-RQ-03 | خروجی داده‌های تاریخی برای تحلیل خارج از خط (CSV/Parquet) |

## 5. نیازمندی‌های عملکردی دقیق

### 5.1 ماژول دریافت داده (Data Ingestion)

|----|----------|

### 5.2 ماژول PINN (مدل هسته)

| ID | نیازمندی |
|----|----------|
| PINN-01 | معماری: ۶ لایه پنهان، ۱۲۸ نورون در هر لایه، تابع فعال‌سازی Swish |
| PINN-02 | ورودی: (r, θ, z, t, T_in(t), P_in(t), m_dot(t), Q_total(t), θ_phys) |
| PINN-03 | خروجی: T_coolant(r,θ,z,t), P(r,θ,z,t), v_z(r,θ,z,t), T_fuel_surface(r,θ,z,t) |
| PINN-04 | تابع هزینه = Loss_MSE + λ₁×Loss_NS + λ₂×Loss_Energy + λ₃×Loss_NeutronicsCoupling |
| PINN-05 | λ_values قابل تنظیم در فایل پیکربندی (پیش‌فرض: λ₁=0.1, λ₂=0.1, λ₃=0.01) |
| PINN-06 | زمان پیش‌بینی هر گام ≤ ۵۰ میلی‌ثانیه روی GPU NVIDIA A100 |

### 5.4 ماژول پیش‌بینی گذرا و شبیه‌سازی سناریو

| ID | نیازمندی |
|----|----------|

| FP-04 | در صورت تشخیص ناهنجاری، شبیه‌سازی ≥۵۰۰ سناریوی «چه-اگر» با تغییر پارامتر در کریدور عدم قطعیت ۹۵٪ |
| FP-05 | افق زمانی هر سناریو: ۳۰۰ ثانیه با گام زمانی ۱ ثانیه |

| FP-07 | خروجی: توزیع آماری زمان تا DNB، زمان تا رسیدن به دمای غلاف ۶۲۰°C |

### 5.5 سیستم پشتیبان تصمیم‌گیری هسته‌ای (Nuclear DSS)

| ID | نیازمندی |
|----|----------|
| DSS-01 | توابع هدف: (۱) بیشینه T_fuel_surface، (۲) بیشینه نوسان فشار، (۳) انحراف از توان تنظیم |
| DSS-02 | متغیرهای تصمیم: توان راکتور (۵۰-۱۰۰%)، دبی پمپ اصلی (۸۰-۱۲۰%)، نرخ تزریق اسید بوریک (۰-۱۰۰ ppm/min) |
| DSS-03 | بهینه‌ساز: NSGA-II (الگوریتم ژنتیک مرتب‌سازی نامغلوب) با جمعیت اولیه ۱۰۰ |
| DSS-04 | زمان اجرای بهینه‌ساز ≤ ۵۰۰ میلی‌ثانیه |
| DSS-05 | خروجی: جبهه پارتو با حداکثر ۱۰ راهکار غیرمغلوب |
| DSS-06 | رتبه‌بندی نهایی بر اساس شاخص «امنیت-اول» = w1×(1 - T_fuel/620) + w2×DNBR |
| DSS-07 | نمایش سه راهکار برتر به همراه: توضیح اقدام، رتبه ایمنی (۱-۵)، احتمال موفقیت (۰-۱۰۰%)، زمان اجرای پیشنهادی |
